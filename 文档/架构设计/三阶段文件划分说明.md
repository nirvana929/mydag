# MyCallypro 三阶段文件划分说明

## 概述

MyCallypro采用清晰的三阶段文件处理流程，确保输入、处理和输出的明确分离。

## 三个阶段

### 阶段1: 输入阶段 - 读取文件
**特点**: 可以从**任意位置**读取文件

#### 支持的输入文件
- **源文件** (.c, .cpp等)
  - 位置：任意磁盘路径
  - 用途：提取行号信息，生成circle.txt配置
  
- **Expand文件** (.c.233r.expand)
  - 位置：任意磁盘路径
  - 用途：GCC生成的RTL中间表示文件
  - 生成方式：`gcc -fdump-rtl-expand -c source.c`

#### 命令行示例
```bash
# 从任意位置读取文件
python3 -m mycallypro /path/to/file.c.233r.expand \
    --export-txt circle.txt \
    --source-file /path/to/source.c \
    --debug
```

---

### 阶段2: 处理阶段 - 中间结果
**位置**: `mycallypro/中间结果/<程序名>/`

**特点**: 所有程序执行过程中生成的**临时文件**都存储在此

#### 目录结构
```
mycallypro/中间结果/<程序名>/
├── debug/          # 调试JSON文件
│   ├── *_control_prefix.json     # 控制流前缀
│   ├── *_post_parse.json         # 解析后数据
│   ├── *_post_callee_info.json   # 调用信息
│   └── *_threads.json            # 线程信息
├── temp/           # 临时DOT文件
└── logs/           # 日志文件
```

#### 文件说明
- **debug/*.json**: 解析和处理过程的调试信息
- **temp/**: 处理过程中的临时图文件
- **logs/**: 执行日志（如果启用）

**注意**: 这些文件仅用于调试和开发，不提供给dag_describe使用

---

### 阶段3: 输出阶段 - 配置文件
**位置**: `mycallypro/配置文件/<程序名>/`

**特点**: 为`test/dag_describe`提供的**最终输出**，采用**扁平化结构**（参考`test/配置文件/`）

#### 目录结构
```
mycallypro/配置文件/<basename>/
├── circle.txt                  # ⭐ 主配置文件（dag_describe输入）
├── <basename>.dot              # DAG图（线程视图）
├── <basename>_full.dot         # DAG图（完整视图，可选）
├── <basename>.c                # 源代码副本（可选）
└── <basename>.c.233r.expand    # expand文件副本（可选）
```

**示例**：produce.c项目
```
mycallypro/配置文件/produce.c/
├── circle.txt
├── produce.c.dot
├── produce.c_full.dot
├── produce.c
└── produce.c.233r.expand
```

#### 命名规则
- **目录名**: 使用源文件基础名（如 `produce.c`）
- **circle.txt**: 固定名称，dag_describe的主要输入
- **DOT文件**: 
  - `<basename>.dot` - 线程视图
  - `<basename>_full.dot` - 完整视图（包含条件节点）
- **源文件**: 保留原始文件名
- **expand文件**: 保留原始文件名

#### 与test/配置文件/对比

**test/配置文件/dag/**:
```
├── circle.txt
└── produce_4.dot
```

**mycallypro/配置文件/produce.c/**:
```
├── circle.txt
├── produce.c.dot
├── produce.c
└── produce.c.233r.expand
```

✅ **优势**：
- 扁平化结构，无子目录
- circle.txt 和 DOT 文件在同一级
- 方便 dag_describe 直接读取
- 结构简洁清晰

#### circle.txt 格式
```
互斥量
producer/while/pthread_mutex_lock2 mutex buf_mutex1 34 produce.c
producer/while/pthread_mutex_unlock4 mutex buf_mutex1 41 produce.c
...

信号量
producer/while/sem_post5 semaphore full1 42 produce.c
consumer/sem_wait1 semaphore full1 50 produce.c
...

条件变量
consumer/if/pthread_cond_broadcast4 condition cond1 61 produce.c
watcher/while/pthread_cond_wait2 condition cond1 76 produce.c
...
```

**格式**: 5列
1. 节点路径（如 `producer/while/pthread_mutex_lock2`）
2. 类型（`mutex`, `semaphore`, `condition`）
3. 变量名（如 `buf_mutex1`）
4. 行号（如 `34`）
5. 文件名（如 `produce.c`）

## 使用流程

### 命令行方式

```bash
# 1. 准备输入文件（阶段1）
# 从任意位置准备源文件和expand文件

# 2. 执行分析（阶段2 + 阶段3）
cd /home/chove/桌面/cally
python3 -m mycallypro <expand_file> \
    --export-txt circle.txt \
    --source-file <source_file> \
    --debug

# 3. 查看输出
# 配置文件: mycallypro/配置文件/<程序名>/
# 中间结果: mycallypro/中间结果/<程序名>/
```

### GUI方式

```bash
python3 mycallypro/gui.py
```

1. 点击"选择 expand 文件"
2. 点击"选择 C 文件"
3. 点击"生成配置文件"
4. 查看 `mycallypro/配置文件/<程序名>/`

## 与dag_describe集成

### 使用配置文件

```bash
cd test/dag_describe
python3 dag_describe.py ../../mycallypro/配置文件/<程序名>/circle.txt
```

### 配置文件的优势

1. **独立性**: 配置文件目录只包含必要的最终输出
2. **清晰性**: 没有调试文件和临时文件的干扰
3. **可移植性**: 可以单独复制配置文件目录给其他工具使用
4. **可追溯性**: 保留了源文件和expand文件的副本

## 目录权限和管理

### 清理中间结果

```bash
# 仅清理中间结果，保留配置文件
rm -rf mycallypro/中间结果/*
```

### 清理所有输出

```bash
# 清理配置文件和中间结果
rm -rf mycallypro/配置文件/* mycallypro/中间结果/*
```

### 只保留配置文件

```bash
# 这是推荐的做法，中间结果可以删除
rm -rf mycallypro/中间结果/*
# 配置文件保留供dag_describe使用
```

## 常见问题

### Q: 为什么要分三个阶段？
A: 
- **输入阶段**：灵活性 - 可以从任意位置读取文件
- **中间结果**：调试性 - 保留处理过程方便调试，但不影响最终输出
- **配置文件**：纯净性 - 只包含dag_describe需要的文件，清晰简洁

### Q: 中间结果目录可以删除吗？
A: 可以。中间结果仅用于调试，删除后不影响配置文件的使用。

### Q: 配置文件可以移动到其他位置吗？
A: 可以。配置文件目录是自包含的，可以整体复制到其他位置使用。

### Q: 如何只生成配置文件不生成中间结果？
A: 不使用 `--debug` 参数即可，这样中间结果目录会创建但基本为空。

## 文件大小参考

以produce.c为例：

**输入（阶段1）**:
- produce.c: ~3.6 KB
- produce.c.233r.expand: ~47 KB

**中间结果（阶段2）**:
- debug/*.json: ~10-50 KB（取决于程序复杂度）

**配置文件（阶段3）**:
- circle.txt: ~700 bytes - 5 KB
- dot/dag.dot: ~2-10 KB
- images/dag.png: ~200-500 KB
- 源文件和expand副本: 同输入大小
