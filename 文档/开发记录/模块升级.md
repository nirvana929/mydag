# 模块升级：解耦线程补边与条件标注

## 背景与目标

当前 `mycallypro` 中线程补边（pthread_create/join）与条件标注（if/while/switch）高度耦合，导致代码难以扩展。本升级计划将这两个功能解耦为独立的 Pass，实现可插拔的管线架构。

## 解耦目标

- 将"线程补边"与"条件标注"从解析与渲染流程中彻底分离
- 实现可插拔的管线 Pass 架构
- 保持现有输出格式与命名约定不变
- 便于后续扩展其他功能（锁竞争、I/O边、异常边等）

## 推荐架构（按职责分层）

### 1. Parser 层
- **职责**：只负责把 expand 解析成统一中间模型
- **文件**：`parser.py`（已存在，需强化）
- **约束**：不夹带任何"补边/标注"逻辑

### 2. IR/Model 层
- **职责**：集中定义"函数、调用、边、标签"的不可变数据模型
- **文件**：`model.py`（已存在，需强化）
- **核心对象**：
  ```python
  CallGraph: {
      functions: Dict[str, Function],
      edges: Set[(src, dst)],
      tags: Dict[node, Set[tag]]
  }
  NodeId: "funcName/callName#seq"
  ```

### 3. Pipeline 层（关键）
- **职责**：一组有序 Pass（纯函数/类），每个 Pass 输入 IR、输出新 IR
- **目录**：`pipeline/`（新建）
- **Pass 列表**：
  - `ThreadEdgesPass`：只解析/补充 pthread_create/join 语义边
  - `ConditionTagPass`：只识别 if/while/switch，加标签、补合流/扇出边
  - 未来扩展：锁竞争标注、I/O边、异常边、函数过滤等

### 4. Export 层
- **职责**：从 IR 渲染 DOT/PNG
- **文件**：`renderer.py`（已存在，需强化）
- **约束**：不做业务逻辑，只看 IR

### 5. Orchestration 层
- **职责**：参数解析、选择 Pass、调用 Export
- **文件**：`cli.py`、`gui.py`、`legacy.py`（逐步瘦身）

## 关键接口设计

### Pass 接口
```python
class Pass:
    def run(self, graph: CallGraph, options: Options) -> CallGraph
    # 约束：不得修改输入 graph，返回新对象
```

### Export 接口
```python
def to_dot(graph: CallGraph, options: RenderOptions) -> str
```

## 与现有代码映射

### 保留并强化的模块
- `parser.py`：作为 Parser 层基础
- `model.py`：作为 Model 层基础
- `renderer.py`：作为 Export 层基础
- `thread_map.py`：join 解析逻辑迁入 ThreadEdgesPass

### 需要重构的模块
- `legacy.py`：从"解析+补边+条件+渲染"混合流程改为管线执行
- `gui.py`：两按钮分别启用不同 Pass 集合
- `cli.py`：参数分发与管线执行

## 重构步骤与里程碑

### 里程碑 1：建立标准 IR 与 Pass 接口
- **目标**：搭建"空壳"，不改现有功能
- **任务**：
  - 在 `model.py` 强化 CallGraph 表示
  - 补充边/标签的不可变操作（返回新图）
  - 新增 `pipeline/` 目录，放 `base.py`（Pass 接口/管线执行器）
- **时间成本**：0.5 天（4h）

### 里程碑 2：抽出 ThreadEdgesPass
- **目标**：迁移线程补边逻辑
- **任务**：
  - 从 `legacy.py` 与 `thread_map.py` 迁移"create/join 补边"到 `passes/thread_edges.py`
  - 让 legacy 调用"Parser → ThreadEdgesPass → renderer"跑通 `--threads-only`
- **时间成本**：1 天（8h）

### 里程碑 3：抽出 ConditionTagPass
- **目标**：迁移条件标注逻辑
- **任务**：
  - 将 if/while/switch 的命名前缀与虚线样式、合流/扇出边生成逻辑搬到 `passes/conditions.py`
  - 让默认模式走 Parser → ThreadEdgesPass → ConditionTagPass → Export
- **时间成本**：1.5 天（12h）

### 里程碑 4：Orchestration 收口
- **目标**：统一管线执行
- **任务**：
  - `legacy.main` 改为：解析参数 → 构造 Pass 列表 → 运行管线 → 导出 DOT/PNG
  - `gui.py`/`cli.py` 仅负责传参与路径，去除业务细节
- **时间成本**：0.5 天（4h）

### 里程碑 5：回归与对齐
- **目标**：确保输出一致性
- **任务**：
  - 回归已有示例，确保 DOT 差异只在预期范围
  - 写少量快照测试（比较 DOT 的结构性内容）
- **时间成本**：0.5 天（4h）

## 时间成本总览

- **总计**：约 3.5 天（28 小时）
- **保守估算**：若只做"非侵入、逐步抽取"，基本可控
- **扩展估算**：若同时重新定义条件合流语义，需 +0.5～1 天

## 风险与对策

### 风险 1：legacy 的解析/编号与条件识别耦合较深
- **对策**：先保持 legacy 的解析产物不变，把"补边/标注"迁移到 Pass 中

### 风险 2：DOT 比对不稳定（文本顺序不同）
- **对策**：渲染前排序稳定化；测试只比较"集合/多重集"

### 风险 3：GUI/CLI 行为变动
- **对策**：保留参数与输出路径不变，只换内部实现

## 预期收益

### 立即收益
- 任何新特性变成"新增一个 Pass"即可接入
- 线程语义与条件语义各自可独立演化/替换
- GUI/CLI 只切换 Pass 组合，易维护、易测试

### 长期收益
- 代码结构清晰，职责分离
- 便于单元测试和集成测试
- 支持插件化扩展

## 实施指导

### 开始前准备
1. 备份当前代码
2. 确认现有功能正常工作
3. 准备测试用例

### 每个里程碑后
1. 运行回归测试
2. 对比输出文件
3. 确认功能完整性

### 完成标准
- 所有现有功能保持不变
- 代码结构清晰分离
- 新功能易于扩展
- 测试覆盖充分

## 文件结构预期

```
mycallypro/
├── pipeline/
│   ├── __init__.py
│   ├── base.py          # Pass 接口与管线执行器
│   └── passes/
│       ├── __init__.py
│       ├── thread_edges.py    # 线程补边 Pass
│       └── conditions.py      # 条件标注 Pass
├── model.py             # 强化 IR 模型
├── parser.py            # 纯解析逻辑
├── renderer.py          # 纯渲染逻辑
├── cli.py               # 参数分发
├── gui.py               # GUI 界面
└── legacy.py            # 逐步瘦身，最终只做管线编排
```

## 注意事项

1. **向后兼容**：确保现有 CLI/GUI 接口不变
2. **输出一致**：确保生成的 DOT/PNG 文件与现有版本一致
3. **渐进式**：每个里程碑都要能独立运行
4. **测试驱动**：每个改动都要有对应的测试验证
