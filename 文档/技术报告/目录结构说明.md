## 💻 主程序目录 (`mycallypro/`)

核心代码和模块实现。

```
mycallypro/
├── __init__.py            # 包初始化
├── __main__.py            # 程序入口
├── legacy.py              # ⭐ 核心解析和生成逻辑
├── gui.py                 # 图形用户界面
├── cli.py                 # 命令行界面
├── parser.py              # RTL解析器
├── renderer.py            # DOT渲染器
├── builder.py             # 构建器
├── model.py               # 数据模型
├── threads.py             # 线程边推断
├── thread_map.py          # 线程映射
├── control_flow.py        # 控制流分析
├── source_binder.py       # 源码绑定
├── exporters.py           # 导出器（circle.txt等）
├── 配置文件/              # 📁 阶段3：最终配置输出
│   └── <basename>/        # 按文件名分类
│       ├── circle.txt     # 主配置文件
│       ├── *.dot          # DOT图文件
│       ├── *.c            # 源代码副本
│       └── *.expand       # expand文件副本
├── 中间结果/              # 📁 阶段2：处理中间产物
│   └── <basename>/
│       ├── debug/         # 调试JSON文件
│       ├── temp/          # 临时文件
│       ├── images/        # PNG图片
│       └── logs/          # 日志文件
└── 源文件/                # 📁 阶段1：输入文件（测试用）
    └── <basename>/
        ├── *.c            # C源文件
        └── *.expand       # expand文件
```

**三阶段划分**：
- **阶段1（输入）**：从任意位置读取源文件和expand文件
- **阶段2（处理）**：中间结果/，临时文件和调试信息
- **阶段3（输出）**：配置文件/，dag_describe需要的最终配置

## 🔍 快速查找

### 我想阅读文档
→ 进入 `文档/` 目录，阅读 `README.md`

### 我想运行测试
→ 进入 `其他文件/测试脚本/` 目录

### 我想查看示例
→ 进入 `测试示例/` 目录

### 我想查看代码
→ 进入 `mycallypro/` 目录

### 我想使用GUI
→ 运行 `python3 -m mycallypro.gui`

### 我想生成配置文件
→ 运行 `python3 -m mycallypro <expand_file> --export-txt circle.txt`

## 📦 文件类型说明

| 扩展名 | 类型 | 说明 |
|--------|------|------|
| `.py` | Python源码 | 主程序和脚本 |
| `.c` | C源码 | 待分析的C程序 |
| `.expand` | RTL展开文件 | GCC生成的中间表示 |
| `.dot` | DOT图文件 | Graphviz格式的调用图 |
| `.png` | PNG图片 | 渲染后的可视化图 |
| `.txt` | 文本配置 | circle.txt等配置文件 |
| `.json` | JSON数据 | 调试和中间数据 |
| `.md` | Markdown文档 | 项目文档 |
| `.sh` | Shell脚本 | 测试和自动化脚本 |

## 🗑️ 清理建议

定期清理以下目录以节省空间：

- `mycallypro/中间结果/` - 中间结果可以重新生成
- `其他文件/临时数据/` - 临时测试数据
- `.git/` - Git历史（如果不需要版本控制）

**保留重要数据**：
- `mycallypro/配置文件/` - 最终配置输出
- `文档/` - 项目文档
- `测试示例/` - 测试用例

---

## 📌 目录设计原则

1. **分离关注点**：文档、代码、测试、数据分离
2. **层次清晰**：每层目录有明确的职责
3. **易于查找**：文档分类索引，测试集中存放
4. **三阶段划分**：输入-处理-输出清晰分离
5. **可扩展性**：便于添加新功能和文档
