# 冗余处理机制说明

## 概述

为了优化重复处理同一个源文件或expand文件的场景，mycallypro实现了混合模式的冗余处理机制。用户可以根据需要选择不同的处理策略。

## 三种工作模式

### 1. 默认模式（覆盖）

**使用方式**：不添加任何额外参数

```bash
python3 -m mycallypro <expand_file> --export-txt circle.txt --output-base <path>
```

**行为**：
- 如果目标目录已存在，直接覆盖其中的文件
- 保持目录结构不变
- 快速简单，适合日常开发

**适用场景**：
- 快速迭代开发
- 已知文件发生变化
- 不在意旧文件保留

### 2. 智能检测模式

**使用方式**：添加 `--smart` 参数

```bash
python3 -m mycallypro <expand_file> --export-txt circle.txt --output-base <path> --smart
```

**行为**：
- 比较输入文件和输出文件的修改时间
- 如果输入文件没有新于输出文件，跳过重新生成
- 输出提示信息：`[SMART] Skipping regeneration, files are up-to-date`
- 节省处理时间和系统资源

**适用场景**：
- 批量处理多个文件
- 不确定文件是否被修改
- 需要优化处理时间

**强制重新生成**：
如果需要在智能模式下强制重新生成，可以配合 `--force` 参数：

```bash
python3 -m mycallypro <expand_file> --export-txt circle.txt --output-base <path> --smart --force
```

### 3. 清理重建模式

**使用方式**：添加 `--clean` 参数

```bash
python3 -m mycallypro <expand_file> --export-txt circle.txt --output-base <path> --clean
```

**行为**：
- 删除已存在的配置文件目录和中间结果目录
- 从头开始重新创建所有文件
- 确保输出目录完全干净
- 输出提示信息：`[CLEAN] Removing existing config directory`

**适用场景**：
- 需要完全重新生成
- 怀疑旧文件存在问题
- 清理测试数据

## GUI 界面支持

在图形界面中，提供了"冗余处理模式"选项框：

```
┌─── 冗余处理模式 ───────┐
│ ☐ 智能检测 (--smart)   │
│ ☐ 清理重建 (--clean)   │
│                        │
│ 默认：覆盖已有文件     │
│ 智能：跳过未修改文件   │
│ 清理：删除后重新生成   │
└────────────────────────┘
```

**使用说明**：
1. 勾选"智能检测"：启用时间戳检查，跳过未修改的文件
2. 勾选"清理重建"：删除旧目录后重新生成
3. 两个选项互斥，勾选一个会自动取消另一个
4. 都不勾选：使用默认覆盖模式

## 实现原理

### 时间戳比较（智能模式）

```python
# 获取输入文件和输出文件的修改时间
input_mtime = input_file.stat().st_mtime
output_mtime = circle_txt.stat().st_mtime

# 如果输入文件没有新于输出文件，跳过生成
if input_mtime <= output_mtime:
    config._skip_generation = True
    return config_dir, intermediate_dir
```

### 目录清理（清理模式）

```python
# 删除已存在的目录
if clean_mode and not getattr(config, '_cleaned', False):
    if config_dir.exists():
        shutil.rmtree(config_dir)
    if intermediate_dir.exists():
        shutil.rmtree(intermediate_dir)
    config._cleaned = True  # 标记已清理，避免重复
```

### 默认覆盖（默认模式）

```python
# 直接创建目录，exist_ok=True 允许已存在
config_dir.mkdir(parents=True, exist_ok=True)
# 后续文件操作会直接覆盖已有文件
```

## 典型使用示例

### 示例 1：首次生成

```bash
# 首次处理文件，使用默认模式
python3 -m mycallypro produce.c.233r.expand \
    --export-txt circle.txt \
    --output-base /path/to/mycallypro
```

**输出**：
```
DBG: [INFO] Exporting circle.txt to: .../配置文件/produce.c/circle.txt
DBG: [INFO] Successfully exported circle.txt
DBG: [INFO] Saved DOT file to: .../配置文件/produce.c/produce.c.dot
```

### 示例 2：智能模式检测

```bash
# 再次处理同一个文件，使用智能模式
python3 -m mycallypro produce.c.233r.expand \
    --export-txt circle.txt \
    --output-base /path/to/mycallypro \
    --smart
```

**输出**（文件未修改）：
```
DBG: [SMART] Skipping regeneration, files are up-to-date
DBG: [INFO] Skipping file generation (smart mode, files up-to-date)
```

### 示例 3：修改文件后重新生成

```bash
# 修改源文件后重新编译expand文件
gcc -fdump-rtl-expand -c produce.c

# 使用智能模式，自动检测到文件已修改
python3 -m mycallypro produce.c.233r.expand \
    --export-txt circle.txt \
    --output-base /path/to/mycallypro \
    --smart
```

**输出**（文件已修改）：
```
DBG: [INFO] Exporting circle.txt to: .../配置文件/produce.c/circle.txt
DBG: [INFO] Successfully exported circle.txt
...
```

### 示例 4：强制清理重建

```bash
# 清理所有旧文件并重新生成
python3 -m mycallypro produce.c.233r.expand \
    --export-txt circle.txt \
    --output-base /path/to/mycallypro \
    --clean
```

**输出**：
```
DBG: [CLEAN] Removing existing config directory: .../配置文件/produce.c
DBG: [CLEAN] Removing existing intermediate directory: .../中间结果/produce.c
DBG: [INFO] Exporting circle.txt to: .../配置文件/produce.c/circle.txt
...
```

## 注意事项

1. **智能模式的局限性**：
   - 只检查expand文件的修改时间
   - 不检查源代码文件的修改（如果单独修改源代码但未重新编译expand，智能模式会跳过）
   - 解决方案：使用 `--force` 强制重新生成

2. **清理模式的风险**：
   - 会删除整个配置文件目录和中间结果目录
   - 如果目录中有手动添加的文件，也会被删除
   - 建议：重要文件应备份到其他位置

3. **模式互斥**：
   - `--smart` 和 `--clean` 不应同时使用
   - 如果同时指定，`--clean` 会优先执行（完全重建）
   - GUI界面会自动处理互斥逻辑

4. **调试信息**：
   - 添加 `--debug` 参数可以查看详细的处理信息
   - 包括时间戳比较、目录清理、文件生成等步骤
